三个根因：

| # | 代码读的位置 | Vapi 实际发的地方 | 后果 |

| 3 | `message.call.recordingUrl` | `message.artifact.presignedMonoUrl` | 录音一个都没存下来 |

第 3 个还有第二层坑：`artifact.recordingUrl` 是**裸 R2 路径**，直接 GET 返回 `400 Authorization`；能用的只有带 SigV4 签名的 `artifact.presignedMonoUrl`。

>
> **（2026-10-29 晚修正）** 录音并非一过期就没了：Vapi 的 `GET /call/{id}` 会**重新签发一份 12 小时有效的下载链接**，只要通话还在 14 天窗口内就还能拉回来。已据此救回 10-14 的两通（840 KB / 804 KB）。

> 最终库存：**14 条永久录音链接，逐条实测 HTTP 200 / `audio/wav` 可播，0 条失效**。

**修复**：逻辑抽到新文件 `src/lib/call-extraction.ts`（纯函数、无副作用、可测），`order.ts` 改为从那里取。

### 🟡 P1 — AI 开场白死循环（10-14 那通）

```
AI  : Handiwork service desk. What's the issue?
客  : Hi. Um, do you guys install TV now?
AI  : What's the issue?      ← 完全无视客户已经说了需求
客  : Do you install TV now?
AI  : What's the issue?      ← 继续复读
客  : What kind of work do you offer
AI  : What's the issue?      ← 复读第三次
```

根因（2026-10-29 深挖后修正，**不是**之前判断的"句号平调"）：**prompt 里把开场白写死成了脚本**。

```
## 3-turn flow (keep it tight)

### Turn 1 — Identify + zip
You: "What's the issue."              ← 这行是字面脚本
Customer: "I have a kitchen sink that's leaking, I'm in 77005"
```

两个问题叠在一起：
1. `You: "What's the issue."` 是 prompt 里**写死的台词**，和 Vapi 的 `firstMessage` 完全重复 —— 模型手里多了一个"万能复读键"。
2. 脚本里客户那句是**陈述问题**（"我水龙头漏了"）。客户**提问**（"你们装电视吗"）不匹配这个形状，模型就认为 Turn 1 还没走完，于是把脚本第一行再念一遍 —— 而它会的只有这一句。

所以客户把需求说得再清楚也没用：**提问这个句式没有对应的应答路径**（当时的 FAQ 和服务清单里都没有"你们做不做 X"这类条目）。

复现证据（用当时的旧 prompt 跑同一段对话，线上 OpenAI）：
```
customer: Hi. Um, do you guys install TV now?
AI:       What's the issue?      ← 与线上事故一字不差
customer: Do you install TV now?
AI:       What's the issue?
customer: What kind of work do you offer
AI:       What's the issue?
```
注意这是**概率性**的：同一模型、同一 temperature 0.2，旧 prompt 有时复现、有时正常 —— 所以它能悄悄活两周。

**修复**（已推到 Vapi，回读确认 v36 / 15370 字符）：
- prompt 里**删掉** `You: "What's the issue."` 那行，并写明"开场白由问候语说过，不是你的台词"
- 新增 **"Answer the question they asked"** 段：**绝不用问题回答问题**，先答，再要 ZIP
- 新增 **"Service quick answers"** 段：14 条"你们做不做 X"的现成一句话答案（TV / 家具 / 管道 / 电 / 空调 / 刷墙 / 补墙 / 洗车 / 围栏 / 窗帘 / 挂画 / 智能家居 / 屋顶 / 你们做什么活"）
- Hard rules 加一条 "Never answer a customer's question with another question"
- `firstMessage` → `"Handy Works service desk. What's the issue?"`（问号，仍保留）

**为什么以前没人发现**：`scripts/test-conversations.js` 需要能连上 `api.openai.com`，而本机长期连不上 —— 这套用例**从来没跑过**，而且它的 20 条用例全是"客户陈述问题"，没有一条是"客户提问"。

**补上的回归网**：
- `src/app/api/admin/prompt-check` —— 受 secret 保护的 OpenAI 透传，让用例能**从线上跑**（线上 OpenAI 可达）
- `scripts/test-prompt-loop.js` —— 把 10-14 的三通真实通话原样多轮回放
- `scripts/test-conversations.js` —— 新增 TC-Q01..Q04（客户提问类）+ 全局禁止复读开场白 + 工具模拟改成真实线上口径 + 修多工具调用崩溃
- `scripts/fixtures/system-prompt-2026-09-30.md` —— 留档当时那份会犯病的 prompt

验证结果：新 prompt 连跑 4 轮 × 3 个场景 = **12/12 全过**；静态校验 **62/62**；旧 prompt 一次即完整复现线上故障。

### 🟡 P1 — end_call 结果标签错误（10-10 那通）

```

               "summary": "Customer asked about roof shingles, payment, hours; no job booked."})
```

客户全程只问了价格、付款方式、周日营业吗，**最后明说 "No. That's it."** —— 这是纯咨询，不是线索。
标成 `accepted` 会往 Alex 的工作队列里塞一条假线索。

**修复**：prompt 新增 **"end_call outcome — pick the one that matches reality"** 段，明确：
- `accepted` = 客户要派人上门（给了名字/回电号/时间，或明确要约）
- `unsure` = 只问了问题 / 要转人工 / 没留名字就挂了
- `rejected` = 完全不接的活
- `urgent` = 安全紧急

并规定 summary 固定格式：`[问题], [zip], [时间], [姓名], [回电号]`
